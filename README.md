## 先看这 30 秒

Fatris 是 BSC 上的排队抽奖游戏：房间分 **10U / 50U / 100U**，每轮 **100 个席位、2 个中奖名额**，没中奖的人可以领回本金 + 一份等值 FTS 空投。

官方每天按时间表放场次（北京时间 00:00 首场、09:30 起加场、15:00 起放满 90 场），席位满了就进不去；奖励也要自己一笔笔去点领取。

**这个小工具就干三件事：**

1. 到点自动入场（按你设的房间和人数区间）
2. 定时把所有能领的退款 / 空投 / 中奖额度领回来
3. 额度够了自动帮你组矿机（可选）

**它不干的事：**不提高中奖率、不预测开奖、不保证赚钱。

## 2026-11 改版必读（v1.1.0）

游戏这次换了新合约，旧版脚本已经**完全失效**（会一直入场失败）。v1.1.0 已适配，同时把新规则做进来了：

- **队列已换新**：新合约 `0xe2E751…96bF`，旧的 `0x88E6…301` 已停用
- **中奖奖品变了**：不再是 U，而是**等额"矿机额度"**；门票会自动换成 FTS（75% 进矿池 / 15% 股东分红 / 10% 运营），额度要在 **48 小时内领取**，过期作废
- **中奖完全随机**：每轮由 Chainlink VRF 链上抽 2 人，**没有任何办法操控中不中奖**；脚本只能决定"中了之后领不领"
- **矿机额度可累积**：额度不会清零，攒到房间阈值（10U 房 100U）就能组矿机
- **组矿机有两种额度**：老系统额度按**固定 100U**（不管你额度是 120 还是 300）；新版额度按**额度实额**支付
- **额度只能老→新**：链上没有"新版额度转回老系统"的接口，所以新版额度做不到固定 100U

> 老系统已停止新排队。没有历史老额度的账号，只能用新版额度按实额组机。

| 你平时要做的 | 它替你做 |
|---|---|
| 盯时间表、抢席位 | 7×24 守着，出块就判断，人数落在区间才入场 |

## 三步开始

### 第 1 步｜下载

到 [Releases](https://github.com/shishengh/FTS-Queue-Bot/releases/latest) 下载最新版：

| 系统 | 文件 |
|---|---|
| Windows | `autofts.ps1` |
| Linux / macOS / Termux | `autofts.sh` |

放进一个**空文件夹**。需要 **Node.js 18+**（Windows 可 `winget install OpenJS.NodeJS.LTS`）。

### 第 2 步｜配置

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File .\autofts.ps1 --init
```

```bash
# Linux / macOS / Termux
bash autofts.sh --init
```

按提示选房间、人数区间、添加账号（私钥只存在本地 `wallets.json`）。**改设置随时用 `--settings`。**

### 第 3 步｜先看再跑

```
--probe      只读勘探：验证合约地址和函数（不需要私钥，不花钱）
--selftest   只读体检：节点、合约、余额、授权、交易预演
--dry-run    全流程演练：交易不上链
--run        正式运行
--stop       停止
```

第一次请严格按 `--probe → --init → --selftest → --dry-run → --run` 走一遍。

> Windows 用户请用 `autofts.ps1`：它会自动收紧钱包文件权限；Git Bash 里跑 `.sh` 版没有这层保护。

## 设置项说明（都能在向导里点，不用改代码）

| 设置 | 默认 | 说明 |
|---|---|---|
| 参与房间 | 10U / 50U / 100U | 可多选；房间没开放会自动跳过 |
| 抢位区间 | 30 ~ 60 人 | 当前轮人数在这个区间才入场，避免挤不进或中签率太低 |
| 抢单延迟 | 0 ms | 开轮后等多久再入场 |
| 手续费 / Gas | 固定 0.05 gwei | 也可改成"跟链上价 + 上限保护" |
| 领取间隔 | 30 秒 | 多久扫一次可领取的轮次 |
| 最低 BNB | 0.005 | 低于这个值只提醒，不中断 |
| **中奖处理** | 自动领取 | 中奖后 48 小时内自动领额度；也可以选"不领取"（放弃该奖励） |
| **组矿机** | 关 | 开启后选模式：只用老额度 / 只用新版额度 / 两者都组 |
| **老系统固定支付** | 100 USDT | 仅老系统模式用；额度再高也只扣这个数 |

## 矿机到底怎么来的（玩家版）

1. **只有中奖才有新额度**。每中一次，额度 += 该房间票价（10 / 50 / 100U）。
2. **额度不清零、可累积**。攒到房间阈值（10U 房是 100U）就能组机。
3. **组机要再付一笔 USDT + 等值 FTS**，组成 LP 锁进游戏，矿机按 **100 天**慢慢释放。
4. **老系统是"固定 100U"**：只要你老额度 ≥ 100U，组机就只扣 100U，额度是 120 还是 300 都一样。
5. **新版是"按额度实额"**：额度 120U 就扣 120U。想省钱就让额度刚好停在 100 再组。
6. **提前撤仓**会退回 USDT 本金腿，但剩余未释放的额度作废。

## 安全与隐私

- **私钥不出本机**：只存在运行目录的 `wallets.json`，不上传、不回传。Windows 版自动收紧文件权限。
- **不做无限授权**：按当前票价/组机金额精确授权，不签空白支票。
- **只读模式可验证**：`--probe` / `--selftest` 不需要私钥、不花一分钱。
- **完全开源**：代码在 `src/`，产物由 `build/build.py` 生成，可自行构建。
- **无后台服务**：脚本只跟 BSC 节点和游戏合约通信。

⚠️ `wallets.json` **就是你的私钥**。别同步网盘、别发聊天工具、别提交 Git，务必用专门的小号钱包。

## 常见问题

**Q：能操控"不中奖"吗？**
不能。每轮由 Chainlink VRF 链上随机抽 2 人，客户端没有任何可影响的输入。唯一能做的是中奖后选择领不领额度（不领则 48 小时后作废，但门票钱也不会退，不建议）。

**Q：新版额度能转回老系统做固定 100U 吗？**
不能。桥接是单向的（`migrateOldQuota` 老→新），合约里没有任何新→老接口。

**Q：中奖了但没在 48 小时内领会怎样？**
奖励作废，额度不补。脚本默认会自动领取；如果你手动关了，记得自己盯着。

**Q：真的能赚钱吗？**
它保证"不漏领"，不保证"一定赚"。收益取决于你中奖的运气和 FTS 的价格。

**Q：会不会把我钱包里的钱转走？**
不会。它只调用入场、领取、授权、组机这几类接口，没有任意转账能力。但私钥是明文存本地的，机器安全靠你自己。

**Q：多开账号会冲突吗？**
不会，每个账号独立计数、独立领取。

**Q：能长期挂着吗？**
可以，服务器 / Termux / 家用电脑都行，自带崩溃重启。安卓记得关电池优化。

## 给开发者

源码在 `src/`，`build/build.py` 把引擎注入两个模板，生成 Releases 里的单文件脚本：

```bash
python3 build/build.py      # 产物在 dist/
```

关键配置：`QUEUE_ADDR`（新队列）、`MINER_MODE`（old/new/both）、`MINER_USD`、`CLAIM_WIN`。更细的字段和原理见源码注释。
