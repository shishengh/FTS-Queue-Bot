## 这是什么

[Fatris（FTS）](https://fatris.fans/dapp/game) 是 BSC 上的链上排队抽奖游戏：有 **10U / 50U / 100U** 三个房间，每轮 100 个席位、2 个中奖名额，没中奖的参与者可以领回返利和 FTS 空投。

轮次不是随时都有——按官方时间表开放（UTC+8 的 00:00 一场、09:30 起逐场开放最多 49 场、15:00 起全部 90 场）。席位一满就进不去了，而该领的奖励也要自己一笔笔去领。

**这个工具就是替你做这两件事：在合适的时间自动参加，把该领的自动领回来。**

它是开源、本地运行的免费工具，不是官方产品，不抽成、不托管资金。你的私钥只存在自己电脑上。

## 为什么需要它

| | 手动玩 | 用脚本 |
|---|---|---|
| 轮次开放时间 | 得自己记着点，错过就没了 | 7×24 自动守着，出块就判断 |
| 席位满了 / 人不够 | 反复刷新页面 | 只在人数落在你设定的区间时才入场 |
| 多个账号 | 一个一个切钱包 | 多账号同时跑，互不干扰 |
| 领返利和 FTS 空投 | 每轮手动点、容易忘 | 定时扫描，能领就自动领 |
| 节点卡了 / 交易没发出去 | 只能干等 | 自动换节点、自动重试、自动补 nonce |

**一句话：它不提高中奖概率，但能让你不错过任何一轮，也不漏领任何一笔 FTS。**

---

## 它具体帮你做什么

- **自动参与**：按你设定的房间和人数区间，自动完成入场，不用守在电脑前
- **自动领取**：定时检查历史轮次，把该退的 U 和该发的 **FTS** 领回钱包
- **多账号**：一个界面管多个钱包，各自独立运行
- **不白花 gas**：入场前先预演，条件不满足或会失败就不发交易
- **断了能自己恢复**：节点超时自动切换，交易掉了自动补，崩溃自动重启
- **先看再跑**：`--probe` 和 `--selftest` 完全只读、不花钱，先确认合约和账号没问题

## 影响与边界（请先看清）

这个工具改变的是**执行效率**，不是游戏结果：

- ❗ **中奖概率完全由链上规则决定**，脚本不改变它，也不预测开奖。每轮 100 席只有 2 个中奖名额，绝大多数轮次是领返利/空投。
- ❗ **每次入场要真实支付 USDT 和 BNB 手续费**，会花钱。请只用能承受损失的资金。
- ❗ **不保证盈利**。返利、空投比例和规则由项目方合约决定，随时可能调整。
- ✅ **能确定拿到的**：不错过轮次、不漏领、不用熬夜、不多发无效交易。

请先确认你所在地区的法规以及 [Fatris 官方规则](https://fatris.fans/dapp/game) 是否允许使用自动化工具。本项目与 Fatris 官方没有任何关联。

## 三步开始

**第 1 步｜下载**：到 [Releases](https://github.com/shishengh/FTS-Queue-Bot/releases) 下载最新版，Windows 选 `autofts.ps1`，其他系统选 `autofts.sh`。放进一个**空文件夹**。

**第 2 步｜配置**：打开终端，跑一次配置向导，按提示选房间、人数区间、添加账号。

```bash
# Windows
powershell -ExecutionPolicy Bypass -File .\autofts.ps1 --init

# Linux / macOS / Termux
bash autofts.sh --init
```

需要 Node.js 18+（Windows 可用 `winget install OpenJS.NodeJS.LTS`）。

**第 3 步｜先看再跑**：

```
--selftest  只读体检，一分钱不花
--dry-run   完整演练，交易不上链
--run       正式运行
--stop      停止
```

第一次务必按顺序走完 `--selftest → --dry-run → --run`。改设置随时再跑 `--settings`。

> Windows 用户请用 `autofts.ps1`，它会自动收紧钱包文件权限；Git Bash 里跑 `.sh` 版没有这层保护。

## 常用设置（都在向导里点选，不用改代码）

| 你想调的 | 在向导里叫 | 说明 |
|---|---|---|
| 玩哪些房间 | 参与房间 | 10U / 50U / 100U，可多选 |
| 人太少/太多不进 | 抢位区间 | 例如 30~60 人之间才入场 |
| 入场快慢 | 抢单延迟 | 默认 0，立即 |
| 手续费 | 手续费 / Gas | 默认 0.05 gwei，也可设为自动跟链上价 |
| 多久查一次可领奖励 | 领取间隔 | 默认 30 秒 |
| 中奖后领不领额度 | 中奖处理 / 组矿机 | 中奖无法操控，只能决定领不领（48 小时内有效） |
| 老额度组矿机 | 中奖处理 / 组矿机 | 老额度 ≥100U 后，固定付 100 USDT + 等值 FTS 组机 |

默认 gas 是 **0.05 gwei**，也就是 BSC 当前的实际水平——不会多付，也不会因为给太低而卡住。

> 2026-11 改版：队列合约已从 `0x88E6…301` 迁到 **`0xe2E751cF79A5Ce03fED12Abf15acFA7383E296bF`**，旧地址房间已全部停用。本版本默认使用新队列（可用 `QUEUE_ADDR` 覆盖）。

## 安全与信任

- **私钥不出本机**：只存在运行目录的 `wallets.json`，不上传、不回传、不联网分发。Windows 版会自动把它的权限锁到当前用户 + 系统账户。
- **不做无限授权**：每轮只授权「刚好这一轮的票价」，用完下轮再授权。
- **只读模式可验证**：`--probe` / `--selftest` 不需要私钥、不花钱，随时可以自己核对。
- **代码完全开源**：想审查就审查，也可以自己从源码构建。
- **免费、无抽成、无后台服务**：脚本只跟 BSC 节点和游戏合约打交道。

⚠️ 即便如此：`wallets.json` **就是你的私钥**。别同步网盘、别发聊天工具、别提交 Git，务必用专门的小号钱包。

## 常见问题

**Q：能不能「操控不中奖」？**
不能。每轮 100 席由 Chainlink VRF 随机抽 2 名中奖者，结果在链上生成，客户端没有任何可影响的输入，脚本只能决定中奖后领不领额度。想稳定拿矿机额度，只能靠老系统的 `formLP` 接口（见下一条）。

**Q：老的「固定 100U 组矿机」接口还在吗？**
还在，但只对老额度生效：老系统队列 `0x94DbcC…77d` 的 `formLP(room)` 要求你的老额度 ≥ 房间阈值（通常 100U），达标后固定支付 100 USDT + 等值 FTS 组机，与额度具体多少无关。向导里「中奖处理 / 组矿机」可以打开，脚本会自动检查额度、授权并组机。老系统已停止新排队，没有历史额度的账号无法凭空组机。

> 桥接是单向的：只有 `migrateOldQuota()`（老 → 新），合约里没有任何「新版额度转回老系统」的接口；新版 `formLP` 的 USDT 腿按你的额度实额收取（额度多少付多少），所以新版额度做不到固定 100U 组机。

**Q：真的能「赚 FTS」吗？**
能自动把该领的 FTS 空投领回来，但领多少由合约规则决定。工具保证「不漏领」，不保证「一定赚」。

**Q：会不会把我钱包里的钱转走？**
不会。它只调用游戏的入场、领取，以及 USDT 的授权接口，没有任何转账能力。但私钥是明文存本地的，机器安全靠你自己。

**Q：多开账号会冲突吗？**
不会，每个账号独立排队、独立计数。

**Q：能一直挂着跑吗？**
可以，挂服务器或 Termux 都行，自带崩溃重启。安卓记得关掉电池优化。

**Q：出问题 / 想要新功能？**
到 [Issues](https://github.com/shishengh/FTS-Queue-Bot/issues) 提，或直接看源码改。
